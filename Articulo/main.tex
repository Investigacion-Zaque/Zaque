\begin{abstract}
La agricultura de precisión ha revolucionado la producción agrícola mediante la incorporación de tecnologías IoT. Sin embargo, gran parte de las soluciones disponibles dependen de conectividad permanente a Internet y servicios en la nube, limitando su implementación en zonas rurales donde la infraestructura de telecomunicaciones es insuficiente. Este artículo presenta ZAQUE, un sistema distribuido de monitoreo agrícola local diseñado específicamente para operar en entornos con conectividad limitada. La arquitectura propuesta integra una red de nodos ESP32, uno configurado como estación principal (MAIN) y múltiples nodos sensores (SENSOR), comunicados mediante WiFi local. Cada nodo incorpora sensores Modbus RS485 para medición multiparamétrica del suelo, módulos GPS para georreferenciación, y almacenamiento local en microSD para garantizar persistencia de datos. El nodo MAIN expone un dashboard web embebido accesible desde dispositivos móviles sin requerir acceso a Internet. El sistema incluye un motor de recomendaciones agrícolas basado en reglas que genera alertas útiles en lenguaje natural para el campesino. Los resultados demuestran la viabilidad de una solución de bajo costo aproximado de USD 100 por nodo capaz de apoyar agricultura de precisión en comunidades rurales con conectividad limitada.
\end{abstract}

\section{Introducción}

La agricultura moderna enfrenta desafíos crecientes: aumento de población global, limitaciones de agua dulce, degradación de suelos y presión por mejorar rendimientos. En este contexto, la agricultura de precisión emerge como estrategia tecnológica fundamental que permite monitorear variables ambientales a nivel microlocal para optimizar recursos naturales.

El Internet de las Cosas (IoT) ha democratizado el acceso a sensores de bajo costo capaces de recopilar datos ambientales. Sin embargo, la mayoría de soluciones IoT comerciales dependen de plataformas en la nube, requiriendo conectividad permanente a Internet. En Colombia, la conectividad rural continúa siendo una barrera para la adopción de tecnologías digitales en el campo.

ZAQUE surge como respuesta a esta brecha: un sistema de monitoreo agrícola que funciona completamente offline en redes WiFi locales, permitiendo que un campesino use la zona móvil de su celular para conectar múltiples sensores distribuidos en su finca y visualizar toda la información desde un navegador web en su dispositivo móvil.

\section{Arquitectura del Sistema}

\subsection{Visión General}

ZAQUE implementa una arquitectura distribuida multinodo con dos roles diferenciados ejecutados en hardware idéntico, basado en ESP32:

\begin{itemize}
\item \textbf{Nodo MAIN}: Estación central que actúa como servidor web, procesador de datos y almacenamiento principal. Ejecuta permanentemente un servidor HTTP local accesible desde el navegador.
\item \textbf{Nodos SENSOR}: Dispositivos distribuidos en el terreno agrícola que ejecutan ciclos de medición periódica, envían datos al MAIN mediante HTTP POST, y entran en deep sleep para conservar energía.
\end{itemize}

La comunicación entre nodos ocurre a través de una red WiFi local, típicamente la zona móvil del celular del campesino, eliminando la dependencia de infraestructura externa.

\subsection{Componentes Principales}

\subsubsection{Nodo MAIN}

El nodo MAIN implementa las siguientes responsabilidades:

\begin{enumerate}
\item \textbf{Adquisición de datos}: Lectura local de sensores Modbus RS485, GPS y batería.
\item \textbf{Servidor web embebido}: Hosting de un dashboard HTML/CSS/JS directamente en el ESP32.
\item \textbf{API REST local}: Endpoints HTTP para recibir mediciones de nodos SENSOR.
\item \textbf{Almacenamiento persistente}: Registro de mediciones en microSD en formato CSV y JSON.
\item \textbf{Procesamiento de recomendaciones}: Análisis de variables agrícolas y generación de alertas.
\item \textbf{Registro de nodos}: Mantenimiento de estado de todos los sensores conectados.
\end{enumerate}

\subsubsection{Nodos SENSOR}

Los nodos SENSOR ejecutan un ciclo repetitivo de bajo consumo:

\begin{enumerate}
\item \textbf{Despertar periódico}: Por defecto cada 30 minutos.
\item \textbf{Lectura de sensores}: Adquisición de mediciones Modbus en aproximadamente 5 segundos.
\item \textbf{Lectura GPS}: Obtención de coordenadas o ubicación por defecto.
\item \textbf{Envío HTTP}: Transmisión de medición al MAIN en aproximadamente 2 segundos.
\item \textbf{Deep sleep}: Entrada a modo de bajo consumo.
\end{enumerate}

Este ciclo permite una autonomía extendida en los nodos sensores, dependiendo de la capacidad de batería, el intervalo de medición y el consumo real del hardware.

\section{Motor de Recomendaciones Agrícolas}

\subsection{Arquitectura del Motor}

El sistema implementa un motor de recomendaciones basado en reglas que analiza mediciones y genera alertas en lenguaje natural útiles para el campesino.

El motor sigue una jerarquía de prioridades:

\begin{enumerate}
\item \textbf{Validación}: Verifica que la medición contiene datos suficientes.
\item \textbf{Alertas críticas}: Identifica condiciones peligrosas inmediatas.
\item \textbf{Combinaciones críticas}: Analiza interacciones entre variables.
\item \textbf{Variables individuales}: Evalúa cada parámetro en rango normal.
\item \textbf{Estado óptimo}: Confirma cuando todo está bien.
\end{enumerate}

\subsubsection{Recomendaciones Individuales}

Para cada variable, el motor genera texto adaptado:

\begin{itemize}
\item \textbf{Humedad}: Incluye valor actual y recomendación de riego.
\item \textbf{pH}: Describe acidez o alcalinidad y sugiere correcciones.
\item \textbf{NPK}: Valora deficiencias y recomienda fertilización.
\item \textbf{CE}: Alerta sobre salinidad acumulada.
\item \textbf{Temperatura}: Advierte sobre estrés térmico.
\end{itemize}

\begin{itemize}

\item Temperatura igual o mayor a 28 $^\circ$C.
\item Combinación crítica presente.
\end{itemize}

Alerta generada:

\section{Estructura del Firmware}

\subsection{Modularización}

El firmware \texttt{zaque\_device.ino} se divide en componentes con interfaces bien definidas:

\begin{enumerate}
\item \textbf{config.h}: Configuración centralizada de roles, pines, WiFi y valores por defecto.
\item \textbf{types.h}: Estructuras de datos e interfaces virtuales.
\item \textbf{sensor\_reader.cpp}: Lectura del sensor Modbus RS485.
\item \textbf{gps\_reader.cpp}: Lectura GPS con fallback automático.
\item \textbf{sd\_logger.cpp}: Almacenamiento en microSD.
\item \textbf{wifi\_manager.cpp}: Gestión de conexión WiFi.
\item \textbf{http\_client.cpp}: Cliente HTTP para nodos SENSOR.
\item \textbf{web\_server.cpp}: Servidor web para nodo MAIN.
\item \textbf{node\_registry.cpp}: Registro de nodos en el MAIN.
\item \textbf{recommendations.cpp}: Motor de recomendaciones.
\item \textbf{dashboard\_html.h}: HTML, CSS y JavaScript embebido.
\end{enumerate}

\subsection{Compilación Condicional por Rol}

En \texttt{config.h}:

\begin{lstlisting}
#define DEVICE_ROLE DEVICE_ROLE_MAIN
\end{lstlisting}

El compilador incluye o excluye código según el rol:

\begin{lstlisting}
#if DEVICE_ROLE == DEVICE_ROLE_MAIN
  // Codigo solo para MAIN
#endif
\end{lstlisting}

Esto permite compartir gran parte del código entre ambos roles.

\section{Manejo de Errores y Resiliencia}

\subsection{GPS Fallback}

Si el GPS no obtiene señal después de un tiempo determinado, el sistema automáticamente usa la ubicación por defecto definida en \texttt{config.h}:

\begin{lstlisting}
#define DEFAULT_LATITUDE 4.663198720911477f
#define DEFAULT_LONGITUDE -74.05499259771824f
\end{lstlisting}

Este mecanismo garantiza que las mediciones nunca se pierden por falta de GPS.

\subsection{SD Logger Robusto}

El logger de SD implementa validaciones:

\begin{enumerate}
\item Verifica que la tarjeta esté correctamente inicializada.
\item Crea archivos con encabezados CSV solo en la primera escritura.
\item Valida la serialización JSON con verificación de bytes escritos.
\item Registra errores en serial para depuración.
\end{enumerate}

\subsection{Reintentos HTTP}

Los nodos SENSOR implementan reintentos con backoff exponencial:

\begin{lstlisting}
sendWithRetry(measurement, max_retries=3)
\end{lstlisting}

Si el MAIN no responde, la medición se almacena localmente para envío posterior.

\hline

\hline

\hline

\hline
Lectura GPS & 100 mA & 1 s \\
\hline

\hline
Deep sleep & 0.5 mA & 30 min - 8 s \\
\hline

Consumo promedio por ciclo de 30 minutos:

\begin{itemize}
\item Ciclo activo: aproximadamente 70 mA durante 8 segundos.
\item Ciclo dormido: aproximadamente 0.5 mA durante 1792 segundos.
\item Promedio aproximado:
\end{itemize}

\begin{equation}
I_{prom} = \frac{70 \times 8 + 0.5 \times 1792}{1800} \approx 0.81 \text{ mA}
\end{equation}

Con batería de 2000 mAh:

\begin{equation}
Autonomia = \frac{2000}{0.81} \approx 2469 \text{ horas} \approx 102 \text{ dias}
\end{equation}

\subsection{Nodo MAIN}

\begin{itemize}
\item WiFi siempre activo: aproximadamente 80 mA.
\item Servidor web activo: aproximadamente 50 mA.
\item Lectura de sensores periódica: aproximadamente 20 mA promedio.
\item Consumo total: aproximadamente 150 mA promedio.
\end{itemize}

El nodo MAIN debe estar conectado a alimentación permanente, como adaptador AC, sistema solar o batería de mayor capacidad con carga.

\section{Ventajas de la Solución}

\begin{enumerate}
\item \textbf{Operación sin Internet}: Funciona completamente offline en red WiFi local.
\item \textbf{Bajo costo}: Aproximadamente USD 100 por nodo completo.
\item \textbf{Escalabilidad}: Soporte de múltiples nodos, limitado principalmente por rango WiFi.
\item \textbf{Almacenamiento seguro}: Datos persistentes localmente en microSD.
\item \textbf{Facilidad de despliegue}: Hardware y software listos para uso en campo.
\item \textbf{Independencia tecnológica}: No depende de proveedores de servicios en la nube.
\item \textbf{Inteligencia local}: Recomendaciones generadas en el dispositivo.
\item \textbf{Bajo consumo}: Autonomía extendida para nodos SENSOR.
\end{enumerate}

\section{Limitaciones Actuales}

\begin{enumerate}
\item \textbf{Rango WiFi}: Limitado por la distancia, obstáculos e interferencias.
\item \textbf{Sincronización}: No hay sincronización avanzada de estado entre nodos.
\item \textbf{Descubrimiento}: El MAIN debe tener dirección fija o mDNS funcionando.
\item \textbf{Dashboard}: La versión actual es básica y requiere mejoras visuales.
\item \textbf{Análisis}: Las recomendaciones se basan en reglas simples.
\end{enumerate}

\section{Conclusiones}

ZAQUE demuestra la viabilidad de un sistema de monitoreo agrícola local, distribuido y de bajo costo para comunidades rurales con conectividad limitada. La arquitectura basada en ESP32 permite capturar variables críticas del suelo, almacenarlas localmente y proporcionar recomendaciones agrícolas sin depender de infraestructura externa.

Las principales contribuciones de este trabajo son:

\begin{enumerate}
\item Arquitectura modular y escalable ejecutable en hardware de bajo costo.
\item Motor de recomendaciones basado en reglas agrícolas.
\item Mecanismos de resiliencia como GPS fallback, reintentos HTTP y almacenamiento local.
\item Consumo energético optimizado para autonomía extendida.
\item Documentación completa y código orientado a software libre.
\end{enumerate}

Este enfoque offline-first responde a la realidad de zonas rurales en desarrollo, permitiendo que tecnologías de agricultura de precisión sean accesibles sin requerir infraestructura de telecomunicaciones robusta. Se espera que ZAQUE sea una herramienta útil para pequeños y medianos agricultores, extensionistas rurales e investigadores agrícolas en entornos con limitaciones de conectividad.
